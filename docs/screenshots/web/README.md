# The Next.js shell

Regenerated by `node tools/screenshots.mjs` from `web/`, with `next start` on
port 3100 and FastAPI on 8020. 28 images: seven surfaces × two widths × two
themes.

**Its own folder, deliberately.** The Jinja surface's screenshots sit in the
parent directory and several names overlap — `login`, `signup`, `home`,
`practice`. Writing here flattened four of them before it was noticed. Both
surfaces are live for the whole migration (`docs/REDIRECTION.md`), so both
sets of evidence have to survive.

**360px is the design case, not an edge case.** It is the width of the cheap
Android phones this product is for, and it is where v1's navigation turned out
to be unreachable — caught by a person opening a screenshot, not by a test.
There is a test for that now (`web/tests/e2e/reachability.spec.ts`), but the
images stay, because a test only checks what somebody already thought to ask.

These are the viewport, not `fullPage`. A full-page capture draws
`position: fixed` elements at their scroll position, which put the tab bar
across the middle of the home page on top of a heading — an artefact that
looks exactly like a layout bug and would have made this folder misleading.

A deliverable, not an assertion. There is deliberately no screenshot-diffing
test: one that fails on a one-pixel shift teaches everyone to regenerate the
baseline without looking, which is the opposite of the point.
